## Critical Issues Identified

### 🔴 ISSUE #1: Single Modification Extraction (THE BIG ONE)
**Location**: `src/llm_pipeline/tweak_extractor.py` line 36-91
**Problem**: The system only extracts ONE `ModificationObject` per review

**Evidence from Assignment**:
> "Are we certain that the system parses out ALL the intended modifications?  
> E.g. If the review says 'I added an egg and halved the sugar' -> these are two discrete modifications!"

**Example Review that Breaks**:
```text
"I used a half cup of sugar and one-and-a-half cups of brown sugar; 
(2) I omitted the water; 
(3) I added a teaspoon of cream of tartar"
```

This review has **3+ discrete modifications**, but the system only extracts one.

**Current Behavior**:
- `extract_modification()` returns a single `ModificationObject`
- The LLM prompt asks for one JSON object, not an array
- Multiple changes get lumped into one modification type

**Required Fix**:
1. Change return type to `List[ModificationObject]`
2. Update prompt to extract ALL modifications as a JSON array
3. Update pipeline to handle multiple modifications per review
4. Each discrete change should be a separate modification with its own attribution

---

### 🔴 ISSUE #2: Random Selection Instead of "Featured" Reviews
**Location**: `src/llm_pipeline/tweak_extractor.py` line 136
**Problem**: `random.choice(modification_reviews)` - picks random reviews

**Evidence from Assignment**:
> "highest voted community-tested modifications aka the 'Featured Tweaks'"

**Evidence from Data**:
Look at `data/recipe_10813_best-chocolate-chip-cookies.json`:
- Reviews have BOTH `has_modification: true` AND `is_featured: true` flags
- The "featured_tweaks" array exists separately

**Current Behavior**:
```python
selected_review = random.choice(modification_reviews)  # WRONG!
```

**Required Fix**:
1. Prioritize reviews with `is_featured: true` flag
2. Use the `featured_tweaks` array if it exists
3. Fall back to highest-rated modifications if featured not available
4. Document selection strategy

---

### 🟡 ISSUE #3: Poor Scalability - Only One Review Per Recipe
**Location**: `src/llm_pipeline/pipeline.py` line 148
**Problem**: Pipeline only processes ONE random review per recipe

**Evidence from Assignment**:
> "Does the system scale beyond the 5 examples we gave?"

**Current Behavior**:
```python
modification, source_review = self.tweak_extractor.extract_single_modification(reviews, recipe)
```

**Expected Behavior** (based on UI mockup description):
- Users should see "line-level diffs explaining which community suggestions were applied"
- Implies MULTIPLE modifications from MULTIPLE reviews should be applied
- The enhanced recipe should aggregate the best community tweaks

**Required Fix**:
1. Process ALL featured modifications (or top N)
2. Apply them sequentially to build truly "community enhanced" recipe
3. Track attribution for each modification source
4. Handle potential conflicts between modifications

---

### 🟡 ISSUE #4: No Validation of LLM Output Quality
**Location**: Multiple files
**Problem**: No evaluation of whether extractions are accurate

**Evidence from Assignment**:
> "Understanding how to build and evaluate AI products"

**Missing Components**:
- No way to verify if extracted modifications match what the review actually said
- No confidence scoring for extractions
- No validation that applied changes actually improve the recipe
- No testing beyond "does it run?"

**Required Fix**:
1. Add evaluation metrics (precision/recall of modification extraction)
2. Create test cases with ground truth
3. Compare extractions against expected output
4. Document evaluation methodology

## Technical Decisions to Document

### Why These Fixes Matter

1. **Multi-modification extraction**: This is the core product value
   - Users want to see ALL the community wisdom, not just one random tweak
   - Real reviews often contain multiple independent improvements
   - Current system loses 50-80% of valuable modifications

2. **Featured review prioritization**: Quality over quantity
   - AllRecipes curates "Featured Tweaks" for a reason
   - Random selection gives equal weight to 1-star and 5-star reviews
   - Product should surface the best modifications, not random ones

3. **Multiple review aggregation**: True community enhancement
   - One person's tweak might be good, but combining 5 featured tweaks is better
   - This matches the AllRecipes UX where you see multiple featured modifications
   - Creates differentiated value vs. just reading reviews manually
